## 2. 新版工具详解 (hccl-trace)

### 2.1 命令行入口与参数

共 5 个 CLI 入口，均为 `python -m tools.diagnosis.<模块>`：

#### 2.1.1 `parse_plog` — plog 解析

```bash
python -m tools.diagnosis.parse_plog <plog> -o <output.csv>
```

| 参数 | 必需 | 说明 |
|------|------|------|
| `plog` | 是 | plog 文本文件路径 |
| `-o, --output` | 是 | 输出 CSV 路径 |

输出：标准化的 semantic CSV（20 列，`SEMANTIC_FIELDS`）

#### 2.1.2 `parse_msprof` — msprof 解析

```bash
python -m tools.diagnosis.parse_msprof <task_time.csv> -o <output.csv> [--node-id node0]
```

| 参数 | 必需 | 说明 |
|------|------|------|
| `task_time_csv` | 是 | msprof task_time.csv 路径 |
| `-o, --output` | 是 | 输出 CSV 路径 |
| `--node-id` | 否 | 默认 node_id（旧数据补全用） |

输出：标准化的 profiler CSV（9 列，`PROFILER_FIELDS`）

#### 2.1.3 `merge_timeline` — 语义-Profiler 合并

```bash
python -m tools.diagnosis.merge_timeline \
  --plog <plog> \
  --task-time <task_time.csv> \
  -o <merged.csv> \
  [--node-id node0] \
  [--summary summary.csv] \
  [--rank-as-device-fallback] \
  [--keep-duplicate-semantic-keys]
```

| 参数 | 必需 | 说明 |
|------|------|------|
| `--plog` | 是 | plog 文件路径 |
| `--task-time` | 是 | msprof task_time.csv 路径 |
| `-o, --output` | 是 | 输出合并 CSV 路径 |
| `--node-id` | 否 | 默认 node_id |
| `--summary` | 否 | 统计摘要 CSV 输出路径 |
| `--rank-as-device-fallback` | 否 | 旧版单机数据 fallback：用 semantic rank 作为 device_id |
| `--keep-duplicate-semantic-keys` | 否 | 保留原始 duplicate 行（默认自动去重） |

输出：
- 合并 CSV（27 列，`MERGED_FIELDS`）：每行包含 `match_status`、`duplicate_semantic`、`duplicate_profiler` + 全部 semantic 字段 + profiler 时间/类型字段
- stdout 打印 key=value 统计指标
- 可选的 summary CSV（`metric, value` 两列）

#### 2.1.4 `visualize_timeline` — SVG 时间线渲染

```bash
python -m tools.diagnosis.visualize_timeline \
  <merged.csv> \
  [--output timeline.svg] \
  [--include-unmatched] \
  [--max-width 28000] \
  [--min-px-per-us 0.025] \
  [--show-gap-threshold 20.0]
```

| 参数 | 必需 | 说明 |
|------|------|------|
| `merged_csv` | 是 | merge_timeline 输出的合并 CSV |
| `--output` | 否 | SVG 输出路径（默认 `<stem>_timeline.svg`） |
| `--include-unmatched` | 否 | 包含未匹配行 |
| `--max-width` | 否 | SVG 最大像素宽度（默认 28000） |
| `--min-px-per-us` | 否 | 每微秒最小像素数（默认 0.025） |
| `--show-gap-threshold` | 否 | 仅显示大于此值（us）的间隙（默认 20.0） |

输出文件（3 个）：
- SVG 时间线：纯标准库生成的矢量图
- `<stem>_timeline_nodes.csv`：详细节点数据
- `<stem>_timeline_gaps.csv`：lane 内连续 task 间间隙分析

#### 2.1.5 `validate_trace` — 质量校验

```bash
python -m tools.diagnosis.validate_trace <merged.csv> [--min-match-rate 95]
```

| 参数 | 必需 | 说明 |
|------|------|------|
| `merged_csv` | 是 | merge_timeline 输出的合并 CSV |
| `--min-match-rate` | 否 | 最低匹配率阈值（默认 95.0） |

输出：
- stdout 打印 key=value 统计
- 退出码：0（通过）或 1（失败）

失败条件（任一满足即失败）：
- `total == 0`
- `match_rate_percent < min_match_rate`
- `duplicate_semantic_rows > 0`
- `duplicate_profiler_rows > 0`

### 2.3 合并策略

merge_timeline.py 采用**三级 fallback**匹配策略：

```
语义记录 ──merge_key 精确匹配──▶ profiler_by_key              ← 第一级（首选）
    │         (node_id, device_id, stream_id, task_id)
    │
    ├── node_id 为空 && device_id >= 0:
    │     ──(device_id, stream_id, task_id)──▶ 唯一匹配时采用   ← 第二级（自动）
    │
    └── --rank-as-device-fallback && node_id 为空 && device_id < 0:
          ──rank→device_id 尝试──▶ 唯一匹配时采用              ← 第三级（显式 opt-in）
```

**语义去重**（默认启用）：
- 同一 merge_key 的多条 semantic 记录按 `_semantic_specificity()` 评分保留一条
- 评分规则：event 优先级（payload/reduce > copy > signal > ack > executor）、phase 非顶层加分、有 slice/peer_rank 加分
- 可通过 `--keep-duplicate-semantic-keys` 禁用

### 2.4 可视化格式

#### 2.4.1 SVG 时间线

- **布局**：按 `(node_id, device_id, rank, stream_id)` 分 lane
- **X 轴**：真实 msprof 时间戳（us），线性比例
- **颜色编码**：9 种 event 类型各有独立填充色+边框色
- **交互**：每个 bar 包含 `<title>` tooltip，悬停显示全部标识符和时间
- **文本标签**：宽度 > 42px 的 bar 显示缩略事件名
- **间隙指示**：同 lane 连续 task 间间隙 > `show-gap-threshold` 时显示虚线+时长
- **图例**：底部颜色图例，自动换行
- **网格线**：X 轴 10 等分竖线
- **零外部依赖**：纯 Python 字符串拼接生成 SVG

#### 2.4.2 辅助 CSV

| 文件 | 内容 |
|------|------|
| `*_nodes.csv` | 每行：node_index, node_id, device_id, rank, stream_id, task_id, phase, event, semantic, step, slice, task_start, task_stop, duration, label |
| `*_gaps.csv` | 每行：node_id, device_id, rank, stream_id, prev_event, prev_phase, prev_step, prev_task_id, prev_stop, cur_event, cur_phase, cur_step, cur_task_id, cur_start, gap |

### 2.6 能诊断的问题

| 问题类别 | 诊断方式 |
|---------|---------|
| **语义-Profiler 匹配率低** | `validate_trace` 报告 match_rate_percent；`merge_timeline` 报告 unmatched_semantic/profiler 计数和 semantic_missing_device_id |
| **Duplicate merge keys** | `merge_timeline` 报告各类 duplicate 指标；`validate_trace` 以 duplicate 行存在作为失败条件 |
| **Task 时间间隙异常** | SVG 时间线直观显示 lane 内连续 task 间的空白/等待区间；gaps CSV 提供精确数值 |
| **Phase/Event 覆盖不完整** | merged CSV 可按 phase/event/semantic 列过滤，检查特定阶段的事件分布 |
| **跨 Rank/Stream 并行度** | SVG 时间线按 lane 分列，直观展示不同 rank/stream 的 task 重叠情况 |
| **特定 step/slice 的任务序列** | merged CSV 支持按 step/slice 过滤，验证每个步骤的事件链完整性 |
| **数据质量门禁** | `validate_trace` 提供 CI 可用的 pass/fail 判定（退出码 + min_match_rate） |

## 3. 旧版工具详解 (cann-hccl)

### 3.1 工具模块一览

旧版共有 **12 个 Python 脚本**，形成更复杂的多级流水线：

| 阶段 | 模块 | 功能 |
|------|------|------|
| 合并 | `hccl_merge_rank_step_timeline.py` | plog + task_time 合并 + 区间推断 + 覆盖分析 |
| 重排 | `hccl_flow_order_table.py` | 按 ring 数据流顺序重排区间行 |
| 提取 | `hccl_extract_hw_markers.py` | 从 task_time.csv 提取 comm-init 硬件 marker 时间 |
| 校准 | `hccl_calibrate_intranode_offsets.py` | 估计同 node 内各 rank 时钟偏移 |
| 校验 | `hccl_clock_alignment_check.py` | 跨 rank 时间戳 spread 分析 |
| 可视化 | `hccl_semantic_task_timeline_graph.py` | SVG 时间线（按 rank+stream lane） |
| 可视化 | `hccl_ack_signal_dependency_graph.py` | SVG 依赖图（RxAck→Signal→Payload 节点+边） |
| 可视化 | `hccl_stage_dependency_graph.py` | SVG 阶段依赖图（简化版，仅 payload 节点） |
| 可视化 | `hccl_wait_relation_graph.py` | SVG 等待关系图 |
| 可视化 | `hccl_nhr_dependency_graph.py` | SVG NHR 双机依赖图（含时钟校准） |

### 3.2 核心合并引擎差异

#### 3.2.1 输入方式

旧版 `hccl_merge_rank_step_timeline.py` 支持：
- **多 rank 独立 task_time.csv**：`--task-time-dir` 目录下 `task_time_<Device_id>.csv` 文件，每个 rank 一个 CSV
- **双节点**：`--node1-log-file` + `--node2-log-file`，含 `--node-rank-offset`（默认 8）处理全局 rank 映射
- **多 plog 文件**：支持分别指定两个 node 的 plog

新版 `merge_timeline.py`：
- **单 task_time.csv**：一个 CSV 包含所有 rank 的行
- **单 plog 文件**：所有 rank 的语义记录在同一文件中
- **单 node_id 参数**：无多 node 独立映射

#### 3.2.2 输出产品

旧版输出 **5 种 CSV**：

| CSV | 内容 |
|-----|------|
| `merged_task_semantic_time_*.csv` | 原始逐行语义-Profiler 合并 |
| `rank_step_send_reduce_intervals_*.csv` | 推断的发送/归约区间 |
| `rank_timepoint_sequence_send_reduce_*.csv` | 时间点序列 |
| `rank_step_send_reduce_wide_*.csv` | 宽格式 per-step 汇总 |
| `merge_coverage_*.csv` | 覆盖诊断（unmatched 统计等） |

新版输出 **1 种 CSV**（含所有信息的 merged CSV）+ 可选 summary。

#### 3.2.3 区间推断

旧版核心差异化能力是**从离散 task 时间点推断连续区间**（`build_intervals()`）：

| 区间类型 | 推断方式 |
|---------|---------|
| `wait_rx_data_signal` | 从 rx_data_signal_start 到第一个 RxAsync/RxWithReduce |
| `send_remote_reduce` | 从 TxAsync/TxWithReduce 开始到该 rank 的下一个 ACK/Signal |
| `reduce_compute` | 从 HcclReduceAsync 开始到结束 |
| `send_remote_copy` | 远程 copy（allgather 阶段）发送区间 |
| `send_payload_marker` | 基于 `aclprofMarkEx` marker 的 payload 发送区间 |
| NHR 事件 | 跨节点 NHR 相关区间 |

**新版无此能力**。新版仅做逐行 task 级匹配，不做区间聚合或推断。

#### 3.2.4 device_id 映射

旧版 `semantic_match_device_id()` 需要处理全局 rank→device_id 映射（两节点场景下 node2 的 local rank 需要 +8 偏移）。新版通过 HCOMM 生产端直接输出真实 `device_id` 避免了此问题。

#### 3.2.5 operation_idx 分配

旧版有 `assign_operation_idx_from_ring_cycle()` fallback：当 executor-level `allreduce_start` marker 缺失时，用 stream-47 SDMA local copy 在 reduce_scatter step 0 处作为 AllReduce 周期边界自动推断 operation_idx。新版无此机制。

### 3.3 可视化差异

#### 3.3.1 时间线

| 特性 | 新版 visualize_timeline.py | 旧版 hccl_semantic_task_timeline_graph.py |
|------|--------------------------|------------------------------------------|
| 输入 | merged CSV（match_status 列） | merged CSV（matched_task_time 列） |
| 过滤 | 按 match_status 过滤 | 按 matched_task_time + operation_idx 范围 + stage 过滤 |
| 布局 | lane = (node, device, rank, stream) | lane = (rank, stream) |
| 颜色 | 9 色，按 event 编码 | 9 色，按 event 编码（色板几乎相同） |
| tooltip | 含全部标识 + 时间 | 含全部标识 + 时间 |
| 间隙 | 虚线 + 时长标注 | 同 |
| 操作过滤 | 无 | `--op-start` / `--op-end` 按 operation_idx 范围过滤 |

#### 3.3.2 依赖图（仅旧版有）

旧版提供 4 种依赖图 SVG，**新版均未实现**：

**A. Ack/Signal 依赖图** (`hccl_ack_signal_dependency_graph.py`)：
- 每 rank/stage/step 最多 3 个节点：`rx_ack_wait`、`rx_data_signal_wait`、`payload`
- 3 种边：
  - `same_rank_sequence`：同 rank 节点串行依赖
  - `right_neighbor_ack_dep`：RxAck(rank r, step s) 依赖右邻居前一步 payload 完成
  - `upstream_data_signal_dep`：Signal(rank r, step s) 依赖上游生产者前一步 payload 完成
- 支持 `--layout stage`（逻辑列布局）和 `--layout timeline`（真实时间 X 轴）
- 支持 `single_ring` 和 `nhr` 拓扑
- 颜色区分：RxAck 红色、Signal 蓝色、Payload 绿色

**B. 阶段依赖图** (`hccl_stage_dependency_graph.py`)：
- 简化版，仅含 payload 节点
- 按硬件 task 视角的流顺序画边

**C. 等待关系图** (`hccl_wait_relation_graph.py`)：
- 跨 rank 的 wait 关系可视化

**D. NHR 依赖图** (`hccl_nhr_dependency_graph.py`)：
- 双节点 level2 NHR 事件可视化
- 含 `calibrate_two_rank_nhr_clocks()` 时钟校准

### 3.4 分析能力差异

| 能力 | 新版 | 旧版 |

## 4. 新旧版架构哲学差异

### 4.1 数据模型

| 维度 | 新版 (hccl-trace) | 旧版 (cann-hccl) |
|------|------------------|------------------|
| Schema | `dataclass(frozen=True)` 不可变 | dict + 独立字段 |
| 规范化程度 | 统一 20+9 字段经过 schema.py | 各脚本独立定义字段和解析 |
| Merge key | 固定四元组 `(node_id, device_id, stream_id, task_id)` | 各脚本按需组合 |
| CSV 列名 | 统一 snake_case | 混合风格（`Device_id`、`task_start(us)`） |

### 4.2 管道设计

| 维度 | 新版 | 旧版 |
|------|------|------|
| 管道阶段 | 3 步（parse → merge → visualize/validate） | 多步（parse → merge → flow_order → extract → calibrate → visualize） |
| 中间产物 | 1 个 merged CSV | 5 种 CSV |
| 模块耦合 | 松耦合（各模块独立 CLI + 包导入双模式） | 紧耦合（后续脚本依赖 merge 产物的特定列名） |
| 扩展性 | 新分析模块可插入 merge 之后 | 需要理解区间推断的输出格式 |

### 4.3 生产端对比

| 维度 | 新版 (HCOMM) | 旧版 (cann-hccl) |
|------|-------------|-----------------|
| 开关变量 | `HCCL_STEP_TRACE=1`（兼容 `HCCL_TASK_SEMANTIC_TRACE=1`） | `HCCL_TASK_SEMANTIC_TRACE=1` |
| Context 机制 | RAII `TaskSemanticScope` + nested `TaskSemanticEventScope` | `SetTaskSemanticTraceInfo()` 直接调用 |
| device_id | HCOMM `deviceLogicId_` 直接注入 plog | 依赖 consumer 端 rank→device 映射 |
| oneShot | ✅ event scope 输出后自动失效 | ❌ |
| 输出字段 | 22 字段含 `device_id` | ~18 字段无 `device_id` |
| TaskType 映射 | `TaskTypeToName()` 10 种类型 | 同 |
| Schema version | ✅ `schema_version[1]` | ❌ |
| Marker 方式 | plog 日志行（无硬件 marker） | plog + `aclprofMarkEx`（硬件流 marker） |

## 6. 关键差异总结

### 6.1 新版优势

1. **数据质量优先**：duplicate 检测+去重、device_id 直接对齐、match_rate 门禁，构成完整的质量保障链路
2. **简洁的管道**：3 步即可从原始数据到可视化+验证，减少中间格式理解成本
3. **统一的不可变数据模型**：`frozen dataclass` 保证数据完整性，`schema.py` 单一事实来源
4. **生产端改进**：RAII scope + oneShot 机制 + device_id 直接注入，从源头减少数据质量问题
5. **CI 友好**：`validate_trace` 的退出码机制可直接接入 CI pipeline
6. **显式 fallback**：`--rank-as-device-fallback` 和 `--keep-duplicate-semantic-keys` 让用户明确选择行为

### 6.2 旧版优势

1. **丰富的分析深度**：区间推断将离散 task 聚合为有意义的等待/传输/计算阶段
2. **依赖图建模**：跨 rank 的 RxAck/Signal/Payload 依赖关系可视化，可直接看出性能瓶颈的因果链
3. **多节点支持**：双节点 NHR 场景的时钟校准和全局 rank 映射
4. **operation 周期识别**：能自动从 task 序列推断 AllReduce 操作边界
5. **时钟校准**：节点内和跨节点时钟偏移估计
6. **硬件 marker 集成**：利用 `aclprofMarkEx` 提供额外的硬件级时间锚点

### 6.3 互补关系

新版和旧版解决的是**诊断流水线的不同层次**：

```
数据质量层    ← 新版聚焦（merge/validate/dedupe/device_id）
    │
    ▼
时间线层      ← 两版共有（SVG 时间线）
    │
    ▼
区间推断层    ← 旧版聚焦（intervals/flow order）
    │
    ▼
依赖分析层    ← 旧版聚焦（dependency graph）
    │
    ▼
因果诊断层    ← 两版均未完整实现
```

## 8. 附录：快速命令参考

### 新版完整流水线

```bash
# 1. 采集（在目标机器上）
HCCL_STEP_TRACE=1 msprof --output=<dir> torchrun ... <workload>

# 2. 合并
cd /path/to/hccl-trace
PYTHONPATH=hccl python -m tools.diagnosis.merge_timeline \
  --plog <plog.log> \
  --task-time <task_time.csv> \
  --node-id node0 \
  -o merged.csv \
  --summary summary.csv

# 3. 可视化
python -m tools.diagnosis.visualize_timeline merged.csv \
  --output timeline.svg

# 4. 校验
python -m tools.diagnosis.validate_trace merged.csv \
  --min-match-rate 95
```

### 旧版完整流水线

```bash
# 1. 合并 + 区间推断
python tools/hccl_merge_rank_step_timeline.py \
  --plog <plog.log> \
  --task-time-dir <msprof_dir> \
  --rank-size 8 \
  --output-dir <out_dir>

# 2. 时间线可视化
python tools/hccl_semantic_task_timeline_graph.py \
  <merged.csv> --output timeline.svg

# 3. 依赖图可视化
python tools/hccl_ack_signal_dependency_graph.py \
  --merged <merged.csv> \
  --intervals <intervals.csv> \
  --topology single_ring \
  --output dependency.svg
```

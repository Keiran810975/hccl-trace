# HCCL-Trace 诊断工具

在配套的带语义打点 HCOMM/HCCL 上采集训练后，用一条命令完成精确关联、依赖构建、
异常检测和源头候选溯源。离线分析只依赖 Python 标准库，不需要 NPU/PyTorch/CANN。
采集仍需匹配的 CANN/msprof；AI_CPU 还需要合法加载配套 Device 包。

## 安装与命令

在项目根目录、自己的 Python 环境中安装；老 pip 需先在该环境升级：

```bash
python3 -m pip install -e .
hccl-diag analyze --capture ./captures/run-001 --mode rolling --output ./results/run-001
hccl-diag analyze --capture ./captures/abnormal --baseline ./captures/normal \
  --mode baseline --output ./results/abnormal
```

也可不安装，在项目根目录把 `hccl-diag` 换成 `python3 -m hccl.tools.diagnosis.cli`。
旧 `run_diagnosis` 和实验运行器保持兼容；新的用户入口才承诺默认最终仅三文件。

- Rolling：需要下述 SDK 或独立核验的 iteration-map。连续前五个正式轮次的同位置、同结构
  任务构成参考；均值、1.5倍、3 MAD，无绝对增量下限。预热、当前和未来轮次不进入参考。
- Baseline：不要求训练 SDK，但仍需真实语义、Rank/Device 和通信实例关联证据。保留原有
  中位数/MAD、默认10us增量门槛及1.5倍规则；结构参考明确标为 structural，不冒充精确身份。
- 两组均有 SDK 时，公开位置、实际通信成员及类型/大小一致才建立显式 Baseline 配对。

旧数据可直接用 `--capture /path/to/run.json`，也可用 `--capture DIR --manifest /path/to/run.json`。
旧 manifest 的路径仍相对其文件解析；已有 iteration-map.json、preparation-map.json 放在采集根目录。

## 仅三个最终文件

```text
results/run-001/
  execution.html
  root_causes.json
  propagation.html
```

执行图保留真实任务与依赖，高亮候选和相关 Wait；点击候选可展示完整的已报告证据路径。
Host 准备延迟按真实观察区间叠加显示，设备任务只作锚点，不添加虚假的 Host→设备边。
JSON 统一 schema v1，含主候选、全部源头候选、慢化程度、参考统计、未定位观察和覆盖率。
传播页面从源头展示到下游 Wait，可跳转 execution 的同一真实 graph_id。
两个 HTML 均内嵌数据、样式和脚本，断网可用，不依赖已删除的中间文件。

默认在成功或失败退出后自动清理本次临时分析空间。**原始采集与正常组只读，不自动删除。**
结果必须是新目录，且不得在输入目录内部。`--keep-debug` 可把中间文件保存在旁边的
`结果名.debug/`，或用 `--debug-dir` 指定独立新目录；最终报告目录仍只有三个文件。

退出码0只表示流水线通过，仍需看 JSON status/coverage；2为参数/输入/绑定错误，
3为语义关联门禁失败，4为构图/诊断失败，5为报告发布失败。
`insufficient_history`、`not_comparable` 不等于“没有异常”，不会静默换模式。

## 采集目录与拓扑

```text
captures/run-001/
  capture.json                  # 可选：共享run_id、实际拓扑、已有operation证据
  nodes/nodeA/
    plog/
    msprof/                     # 完整PROF目录，含 consolidated DB、host/start_info
    calls/rank-9.jsonl          # SDK自动写入的身份和公开调用
  nodes/nodeB/...
```

节点名称任意合法，节点卡数可以不相等，全局 Rank 可不连续。身份来自 SDK/runtime
或已有 manifest；缺失时可用 `--topology` 提供并与实际 DB 核对：

```json
{"ranks": [
  {"node_id": "nodeA", "user_rank": 9, "device_id": 2},
  {"node_id": "nodeB", "user_rank": 31, "device_id": 6}
]}
```

无 SDK 时，也可给各节点 runtime.json：`{"ranks":[{"user_rank":9,"device_id":2}]}`。
不按目录名、Rank 或 LOCAL_RANK 推断设备。每节点需唯一的前台 per-device DB，
后台采集应在采集配置中独立保存，不能混入相同设备的多份 DB 后猜前台。
长 HOST 采集遇任务编号回绕时，新入口会复用权威 batch 导出，在自己的临时空间生成
身份增强 DB；已增强的 DB 直接使用。必须保留原始 PROF 目录及官方
`device_*/sqlite/hccl_single_device.db`，缺失或歧义即失败，不按序号猜 batch；不会套用到 AI_CPU。

## 在自己的训练中记录位置

每节点在原有本地训练命令外包 msprof；下列路径与命令均换成用户自己的：

```bash
export LD_LIBRARY_PATH=/path/to/matching/lib64:$LD_LIBRARY_PATH
export HCCL_STEP_TRACE=1 ASCEND_GLOBAL_LOG_LEVEL=1
export HCCL_TRACE_RUN_ID=run-001 HCCL_TRACE_NODE_ID=nodeA
export HCCL_TRACE_CALLS_DIR=/captures/run-001/nodes/nodeA/calls
export ASCEND_PROCESS_LOG_PATH=/captures/run-001/nodes/nodeA/plog
msprof --application="$ORIGINAL_LOCAL_LAUNCH_COMMAND" \
  --output=/captures/run-001/nodes/nodeA/msprof --hccl=on --task-time=on --type=db
```

各节点 run_id 一致，node_id 和目录独立；原有分布式启动配置不变。

```python
from hccl_trace import Trace

with Trace.from_environment(device_id=actual_profiler_device_id) as trace:
    trace.group("dp", dist.get_process_group_ranks(dp_group))
    for iteration in range(total_iterations):
        with trace.iteration(iteration, stage="measured"):
            # 原有计算照常执行。
            with trace.collective(group="dp", call_site="layer3.gradient",
                    operation_type="AllReduce", element_count=tensor.numel(),
                    dtype="float32", reduction="sum"):
                dist.all_reduce(tensor, group=dp_group)
            # 仅在训练原本已有、已验证的设备完成边界之后调用。
            existing_user_completion_boundary()  # 替换为训练本来已有的真实完成边界
            trace.completion_boundary()
```

SDK 不同步设备、不创建 NPU task、不改算法。同一 Trace 不接受跨线程并发提交。
Python 返回或只挂接设备流的 Work.wait() 不是设备完成；无真实完成边界时宁可绑定失败。
不同 group 分别注册实际成员，位置是 group/call_site/occurrence，不依赖 Block/Bucket。
同位置重复调用自动编号。可选 preparation_start_raw_ns 记录实际 Host 准备起点。

绑定识别 AllReduce、AllGather、ReduceScatter 等 collective；element_count 填该 HCCL API
的实际 count 语义。AI_CPU 的 DB/API 通过 connectionId 精确对应；HOST 的 runtime launch
需以相同 globalTid/startNs/endNs 连接到具名 HCCL API，差1ns也不接受。再核对类型/dtype/count、
公开时钟区间和实际完成上界，仅接受唯一完整对应，并验证通信域所有参与 Rank。
DB 缺归约操作符时明确输出 reduction_verified_in_database=false。
若多个通信域仍歧义，可在 trace.group(..., db_group_name="实际DB通信域") 提供事实，
不按时间最近、名字相同或调用序号补配。异步宽区间仍可能需框架适配点。

DDP/FSDP 内部通信需要通信 Hook；包住整个 backward 不会自动标记每次内部 collective。
非固定 Transformer 示例为 examples/diagnosis_collectives.py；仅改原启动参数和设备配置。

## 支持边界

- 通用化针对受支持 HCCL 路径的可观测任务，不保证所有算法、传输或动态训练都完整有语义。
- 多机无 SDK 时，需 manifest/capture 中独立证明的共享 operation；相同 DB 名称不是跨机证据。
- Copy 变慢不独立证明 SDMA 竞争，候选 physical_cause 仍可为 unknown。
- Baseline 当前根因筛选覆盖设备执行慢化，不包含 Host 准备区间的溯源；有 SDK 时建议
  用 Rolling 诊断此类提交前延迟。成功生成报告不等于本次异常已被定位。
- 无校时只报告跨机拓扑和本地时长。可用 --require-clock-alignment 要求采集期有效前后探针，
  软件对齐仍不等于硬件完成证据或全局精确关键路径。
- RDMA 门铃耗时不是逐笔 Send/Write/Read 的纯传输完成时间。
- 传播页只展开已有证据，不穷尽下游，不把并发 Wait 增量相加当作 workload 损失。
- 不自动 SSH 部署用户训练，不修改共享驱动、验签、设备策略或其他人的容器。

# 910C双机实验运行指南

代码分支：[nf](https://github.com/Keiran810975/hccl-trace/tree/nf)。环境记录日期：2026-10-22。

## 1. 多机Workload信息

| 项目 | 配置 |
|---|---|
| 节点与Rank | Node0 + Node2，每机2 Rank，共4 Rank |
| 负载 | Transformer形状的合成计算/通信负载，不是完整模型训练 |
| 计算 | BF16 GEMM/GELU；tokens=2048、hidden=8192、FFN=32768 |
| 每轮结构 | 8个Block，每Block执行3次FP32 SUM AllReduce，共24次 |
| 通信桶 | 每Block依次128、256、512MiB |
| 每轮输入量 | 每Rank 7GiB；这是collective输入量，不是网卡实际流量 |
| 正式轮数 | 10轮预热 + 50轮测量 |
| 短预检轮数 | 1轮预热 + 2轮测量，计算形状和桶大小不变 |
| 默认注入位置 | Rank2 / measured iteration25 / block3 / bucket1，均从0编号 |

测试集支持调用前延迟、网卡限速、Copy竞争、计算竞争、通信竞争。
延迟默认是在指定AllReduce调用前sleep，不是内部kernel延迟；后台竞争默认覆盖iteration25–29。
目前大负载已跑通正常组及四种软件注入短预检，尚未完成大负载正式语义诊断。

### 启动短预检

两机同时运行下面命令：Node0设`NODE_RANK=0`，Node2设`NODE_RANK=1`。

```bash
export NODE_RANK=0  # Node2改为1
"$PYTHON" test/two_node_suite.py run-node \
  --case /workspace/two-node-smoke/cases/smoke-2n4r-main-i0-s20261022-normal.json \
  --cluster /workspace/two-node-cluster.json --node-rank "$NODE_RANK" \
  --output /workspace/two-node-runs --attempt smoke-001 \
  --execute --no-profile --timeout 240
```

`--no-profile`只运行负载，不采集msprof DB；省略`--execute`只打印启动计划。
两端case和attempt保持一致；重试换新attempt，每例两机结束后再启动下一例。

### 正式运行与异常注入

正式样例将上述case改为：
`/workspace/two-node-core/cases/2n4r-main-i25-s20261022-normal.json`，
attempt改为`capture-001`，timeout改为1800，并去掉`--no-profile`。

**正式语义采集须先合法加载配套nf Host/Device包。当前官方Device包只适合负载预检，
仅去掉no-profile不能补齐Device语义。** 涉及临时验签时须获得授权、确认整卡空闲并设置回滚；
公共测试脚本不会自动修改验签。加载步骤见[已有双机记录](../hccl/tools/diagnosis/nf-authorized-two-node-validation.md)。

先运行normal，再把case文件名中的`normal`替换为以下后缀：

- `progress_delay-20`：指定位置调用前延迟20ms。
- `copy_contention-1`、`compute_contention-1`、`communication_contention-1`：
  两机命令均加`--allow-background`；并发量也可选2或4。
- `nic_limit-75`：也可选50或25，需要已验证的RoCE限速接口及`--allow-network-change`，未配置时不要运行。

通信竞争还需在cluster的`shared_path_evidence`记录实际共享路径。
完整异常参数见[测试集说明](双机异常测试集与Workload说明.md)。

输出在`/workspace/two-node-runs/<case-id>/<attempt>/node0或node1/`；
其中node1是物理Node2。包含执行记录、各Rank结果、注入事件，以及启用采集后的plog和msprof DB。
需要离线诊断时，收集两机前台数据并按
`test/fixtures/multinode-run.example.json`填写真实设备和调用绑定，然后执行：

```bash
python3 -m hccl.tools.diagnosis.run_diagnosis run.json -o replay
# 异常组可增加 --baseline-dir replay-normal/NORMAL_RUN_ID
```

# 统一采集与诊断

## 最短操作

在自己的训练环境安装一次：

```bash
python3 -m pip install -e .
```

确认原训练可运行、合法部署匹配的语义Host/Device，并接入`hccl_trace.Trace`后：

```bash
hccl-diag capture -o capture -- torchrun ... train.py
hccl-diag analyze capture
```

`torchrun ... train.py`必须替换成原来能正常训练的完整启动命令，不是照抄省略号。
`capture`也可简写为`cap`，`analyze`也可简写为`diag`。不需要传单机/多机、策略版本或Rolling模式。
默认输出`capture-report/`；需要另取名或保留完整图时：

```bash
hccl-diag analyze capture -o result --keep-debug
```

指定`--debug-dir evidence`会自动保留完整中间证据，无需再写`--keep-debug`。
不保留debug时，临时完整图会删除，但原始采集输入不删除，后续仍可重新分析。

## 采集前提

- 采集仅在Linux/CANN训练节点运行，使用系统已有msprof；安装Python工具不会安装或替换通信库。
- 必须是同源码配套、保留必要RUN语义/地址日志的低日志Host/Device；否则WARNING配置可能缺身份事实。
  构建、加载和权限恢复见[完整教程第3节](从零开始运行训练诊断.md#3-准备配套hostdevice库)。
- 原训练需要SDK的真实Rank/device、通信域、调用位置、iteration和设备完成边界；设备ID不从Rank猜。
  [训练接入示例](从零开始运行训练诊断.md#6-换成自己的训练任务)仍适用。
- 工具只包装原训练命令，不加载包、不改驱动/验签/共享策略，不向原训练插入同步或额外通信任务。
- 固定L1/HCCL/ACL开启、PMU关闭、全局WARNING。基础TASK/API仍可能采集，不宣称已在线过滤所有计算任务。
- msprof退出0和SDK日志完成不等于训练数值正确，也不等于诊断必定命中；实际训练应保留自己的数值验收。
- 采集返回成功要求每份SDK日志有真实调用、对应完成边界和最终结束记录；空日志、缺完成或结束后续写均拒绝。
  Ctrl+C或SIGTERM会有界清理本次包装器的自有进程组并保留失败采集，不停止其他训练或服务。

## 多机同样操作

每个节点分别用同一个`run-id`包装自己的原训练启动命令；节点名默认取真实hostname。
原训练的node-rank、master地址等仍由原启动器设置，诊断工具不猜测或改写它们：

```bash
hccl-diag capture -o capture --run-id training-001 -- 原节点训练启动命令
```

各节点的输出结构相同：

```text
capture/nodes/HOSTNAME/
  plog/
  msprof/                 # consolidated msprof_*.db
  calls/                  # Trace SDK公开位置及完成边界
  collection.json
  profiler.log
```

使用共享输出时，各节点写不同hostname子目录，不覆盖彼此。
若各节点本地存储，先完整传到分析机器的不同目录，再汇集：

```bash
hccl-diag join node0-capture node3-capture -o capture
hccl-diag analyze capture
```

join拒绝不同run_id、重复节点、软链和未结束的SDK日志；逐文件SHA校验副本，原输入不删除。
已有`capture.json`声明的节点内自定义`calls_dir`和校时文件会保留，不强制改回默认布局。
单机不需要join。离线分析从实际输入识别节点数，不是从Rank数或节点命名猜测。
需要跨机时间传播时，仍须保留采集期前后校时探针；包装器不会凭空生成校准。
缺校时仅报告本地时长与已有拓扑/边界，不能跨节点直接相减或声称全局因果计时。

## 自动选择和报告

| 真实输入 | 自动路径 |
|---|---|
|一个节点，任意已声明Rank/设备|已验证的局部依赖簇＋严格公开Host迟到选择|
|两个及以上节点|当前P95全量任务群辅助单簇排序＋严格Host证据|

始终只发布一个胜出簇/Host区间，簇内候选平行。多机通信竞争、RoCE和正常误报仍有已知限制，
不能把已知SDMA开发样本的改善冒称任意训练准确率。

输出只有`execution.html`、`root_causes.json`、`propagation.html`。
新报告删除关键路径模型/收益，保留实际任务耗时、参考、慢化、位置和真实依赖传播证据。
默认执行图是候选所在正式轮的原图切片，不是完整采集；`--keep-debug`保留全量中间图，原始输入始终只读。
没有被胜出簇解释的慢Wait仍在`unresolved_observations`中；它们不是新增根因候选。
网页仅展示当前切片内前200条未归因观测，并标明完整/当前/展示数量；JSON不截断这些事实。
完整分析的质量计数不会因报告切片而清零；只有语义证据的路径也不会提升为observed或exact。
每次使用当前轮之前连续五个正式轮的均值作参考，最初五轮不评分；持续异常可能污染滚动参考，仍是待解决限制。
已有独立正常采集时可用`hccl-diag analyze abnormal --baseline normal`，使用中位数而不是Rolling均值。
两次SDK采集的通信位置、成员、类型、数据量及声明的reduction须一致；声明一致不等于已由DB验证归约语义。

## 项目目录

| 目录/入口 | 用途 |
|---|---|
|`hccl.tools.diagnosis.cli`|唯一用户命令入口|
|`recommended_policy.py`|单机/多机自动选择，不让用户选择实验版本|
|parser、binder、graph、propagation模块|两条路径共用的事实和依赖基础设施|
|`hccl_trace/`|训练公开位置SDK|
|`test/`|测试、采集保护和受设备授权约束的实验编排，不是用户诊断入口列表|
|`test/archive/diagnosis_20261108/`|11个已替代的评分/回放实验入口，仅供复现|
|`artifacts/`、`test/out/`|既有结果、原始数据和验证证据；本次不清理|

旧脚本的隐藏CLI参数和函数只为历史回归兼容，正常使用无需了解。
本次整理未更新服务器活动快照，也没有重跑旧实验。

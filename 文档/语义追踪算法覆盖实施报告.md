2026-08-18 检查 `test/out/Ring` 后确认：通用 `AlgTemplateBase` 不拥有 direct 模板中的
`userRank_` 成员。Standard Ring 的日志直接暴露了该编译错误；对另外两个分支的同类源码审计
发现 `ReduceScatterMesh` 和 NHR 通用模板也存在相同问题。修复后，Standard Ring 使用函数参数
`rank`，普通 Mesh RS 使用 `interRank_`，NHR 顶层和分步函数分别使用 `rank`、
`stepInfo.myRank`。这些值在当前单机 combine plane 中同时作为语义 `user_rank` 和
`comm_rank`；未来增加多机 rank 域 context 时需重新区分原始 user rank 与子通信域 rank。

同日设备复测进一步确认三个强制算法路径均通信正确但新增语义为 0。plog 明确显示这些路径使用
FFTS：`DispatcherGraph` 在创建 Notify、SDMA、Reduce、RDMA 等 graph task 后，仅当 msprof
addition-info 已订阅时才调用 profiling callback。`HCCL_STEP_TRACE=1` 虽已使算法 scope 生效，
但 task callback 未执行，`TaskData` 无法捕获 TLS 语义快照。修复在三个分支中统一将 callback
条件扩展为“addition-info 已订阅或语义跟踪已开启”；addition-info 的订阅状态与上报逻辑不变，
语义-only 路径仍由 `TaskProfiling::Run` 直接输出带 `ffts_ctx_id` 的语义记录。

## 2. Standard Ring

### 2.1 修改文件

- `hcomm/src/algorithm/base/alg_template/temp_reduce_scatter/reduce_scatter_ring.cc`
- `hcomm/src/algorithm/base/alg_template/temp_all_gather/all_gather_ring.cc`

### 2.2 语义合同

| 字段 | 约定 |
|---|---|
| `algorithm` | `ring` |
| `phase` | `reduce_scatter`、`allgather` |
| `step` | 当前数据块所在的 Ring 因果轮次，范围 `0..rank_size-2` |
| `slice` | 当前 ACK、发送、接收、reduce/copy 对应的逻辑数据块 |
| `peer_rank` | 左/右 link 的真实 remote rank；本地 copy 使用无效 rank |

ReduceScatter 的首发属于 `step=0`；循环中的接收属于当前 step，索引递减后的下一次
发送属于 `step=i+1`；最终接收 reduce 属于 `rank_size-2`。AllGather 每次循环的
ACK、发送和接收共享该轮 `step=i`。

公共 `Sender`/`Reducer` 继续负责生成 one-shot payload/reduce/copy 事件，模板只提供
phase、step、slice、peer 和 algorithm 上下文。AllGather 的直接 `TxAsync`/`RxAsync`
分别增加 one-shot `tx_payload_start` 和 `rx_payload_copy_start`。

单 rank 实际发生的本地拷贝记录为 `copy_start/hccl_local_copy`；没有物理 task 的 no-op
不生成伪记录。910A NIC 裁剪 chunk 路径不在本轮 910B/910C AllReduce 范围内。

## 3. Mesh

### 3.1 修改文件

- `hcomm/src/algorithm/base/alg_template/temp_reduce_scatter/reduce_scatter_mesh.cc`
- `hcomm/src/algorithm/base/alg_template/temp_reduce_scatter/reduce_scatter_mesh_atomic.cc`
- `hcomm/src/algorithm/base/alg_template/temp_all_gather/all_gather_mesh.cc`
- `hcomm/src/algorithm/base/alg_template/temp_all_gather/all_gather_mesh_atomic.cc`
- `hcomm/src/algorithm/base/alg_template/temp_all_reduce/all_reduce_mesh_opbase.cc`
- `hcomm/src/algorithm/base/inc/all_gather_mesh_pub.h`
- `hcomm/src/algorithm/base/inc/all_gather_mesh_atomic.h`

### 3.2 语义合同

| 模板族 | `algorithm` | `phase` | `step` |
|---|---|---|---|
| 普通 Mesh RS/AG | `mesh` | `reduce_scatter`、`allgather` | 固定 `0` |
| Atomic Mesh RS/AG | `mesh_atomic` | `reduce_scatter`、`allgather` | 固定 `0` |
| `TEMPLATE_ALL_REDUCE_MESH_DIRECT` | `mesh_direct` | `reduce_scatter`、`allgather` | 固定 `0` |

`slice` 始终表示 task 实际操作的数据块，而不是 peer 编号的简单副本：

- RS 发送/远端 reduce 使用目标 rank 的 slice，接收/本地 reduce 使用本 rank slice。
- AG 发送使用本 rank slice，接收/远端 copy 使用 peer slice。
- data signal 延续其对应的数据方向，避免把 peer 与 slice 混为同一身份。

普通 Mesh 的 `Sender`/`Reducer` 复用公共 one-shot 事件。Atomic 与 Mesh Direct
直接调用 `HcclReduceAsync`、`HcclD2DMemcpyAsync` 和 data signal，因此在调用点增加
one-shot 事件。Mesh Direct 的远端 reduce 使用
`tx_payload_start/link_tx_payload_reduce`，体现该 task 由本 rank 发起并写入 peer。

AllGather 基类增加一个受保护的虚拟算法名方法，使 Atomic 子类执行共同的本地 copy
路径时仍输出 `mesh_atomic`，避免同一次算法出现混合 algorithm 标签。

LocalNotify 以及用于多流拼接的零字节 task 暂时保持 profiler-only：前者已有 msprof DB
物理 Notify 关系，后者不是数据传输，均不应伪装成 payload。Standalone
`TEMPLATE_REDUCESCATTER_MESH_DIRECT`/`TEMPLATE_ALL_GATHER_MESH_DIRECT`、small-count、
Oneshot、Chunk Mesh 和 AIV 不属于本轮 AllReduce COV-003。

## 4. NHR

### 4.1 修改文件

- `hcomm/src/algorithm/base/alg_template/temp_reduce_scatter/reduce_scatter_nhr.cc`
- `hcomm/src/algorithm/base/alg_template/temp_all_gather/all_gather_nhr.cc`
- `hcomm/src/algorithm/base/alg_template/temp_all_gather/all_gather_nhr_pub.h`
- `hcomm/src/algorithm/base/alg_template/temp_reduce/reduce_nhr_oneshot.cc`
- `hcomm/src/algorithm/base/alg_template/temp_reduce/reduce_nhr_oneshot_pub.h`
- `hcomm/src/algorithm/base/alg_template/temp_broadcast/broadcast_nhr_oneshot.cc`
- `hcomm/src/algorithm/base/alg_template/temp_broadcast/broadcast_nhr_oneshot_pub.h`
- `hcomm/src/algorithm/base/alg_template/temp_all_reduce/all_reduce_nhr.cc`
- `hcomm/src/algorithm/base/alg_template/temp_all_reduce/all_reduce_nhr_oneshot.cc`

### 4.2 语义合同

| 模板族 | `algorithm` | `phase` | `step` |
|---|---|---|---|
| 普通 NHR | `nhr` | `reduce_scatter`、`allgather` | 当前模板 hop，范围 `0..ceil(log2(rank_size))-1` |
| NHR-Oneshot | `nhr_oneshot` | `reduce`、`broadcast` | 各阶段当前树形 hop，范围 `0..ceil(log2(rank_size))-1` |
| 单 rank copy | 与所属模板一致 | `allreduce_executor` | 固定 `0` |

每个 hop 使用 `GetStepInfo()` 的真实 `fromRank`/`toRank` 设置 `peer_rank`，覆盖 SDMA 和 RDMA
分支的 ACK、payload、reduce/copy、data signal、finish-ack 与可选 barrier。普通 NHR 一个物理 task
可能处理合并后的多个连续 slice；现有 schema 只有单值 `slice`，因此记录该 hop 对应方向的首个逻辑
slice 作为稳定代表，不为同一物理 task 伪造多行语义。

单机设备测试需显式设置 `HCCL_ALGO=level0:ring;level1:NHR`，但该配置本身不足以强制
`AllReduceComm`；还必须由 common topology 或 selector fallback 进入该 executor，并以选择日志确认
在 `COMM_COMBINE`/`COMM_COMBINE_ORDER` 上实际选择 NHR 模板。总字节数
不大于 256 KiB 时应命中 `TEMPLATE_ALL_REDUCE_NHR_ONESHOT`，更大数据应命中
`TEMPLATE_ALL_REDUCE_NHR`。

本分支没有覆盖 NHR-V1，也没有增加 Level1/Level2 context、跨节点 rank 域或 protocol identity；
因此它可以用于当前单机 combine-plane 测试，但不构成多机 hierarchical NHR 完整覆盖声明。

## 6. 设备测试方案

### 6.1 公共步骤

1. 分别从目标功能分支构建 HCOMM，记录 branch、commit、构建命令和产物校验值。
2. 部署该分支动态库，记录 `LD_LIBRARY_PATH`、运行时 DevType、设备产品名和 HCCL revision。
3. 使用 `HCCL_STEP_TRACE=1` 运行 workload，同时采集 plog 和 msprof DB/JSON。
4. 保存算法选择日志，确认实际 executor/template，不以测试名称推断选路。
5. 运行 `test/run_step_trace_function_test.sh`，要求 semantic 非空、匹配率不低于 95%，
   semantic/profiler duplicate key 均为 0。
6. 输出 `(algorithm, phase, step, slice, peer, event, semantic task kind, profiler task kind)`
   分布并人工抽查边界 rank。

### 6.2 Standard Ring

- 建议 ID：`DT-910B-AR-RING-2P-001`、`DT-910B-AR-RING-8P-001`。
- 覆盖 2P 边界和 8P 完整轮次，至少包含 in-place、out-of-place 两种 buffer 关系。
- 选择日志必须落到 `ReduceScatterRing` 和 `AllGatherRing`，不能误用
  concurrent-direct Ring 产物。
- 预期 RS/AG 的 link 事件均在 `0..rank_size-2`，peer 为 Ring 邻居，最终 RS slice
  收敛到本 rank。

### 6.3 Mesh

- Atomic：910B、deterministic disabled、非 INT64、reduce op 非 PROD，建议
  `DT-910B-AR-MESH-ATOMIC-8P-001`。
- Normal：使用 deterministic enabled、INT64 或 PROD 触发非 atomic fallback，建议
  `DT-910B-AR-MESH-NORMAL-8P-001`。
- Mesh Direct：确认选择 `AllReduceMeshOpbaseLoopExecutor` 和
  `TEMPLATE_ALL_REDUCE_MESH_DIRECT`，建议
  `DT-910B-AR-MESH-DIRECT-8P-001`。
- 三组数据都要求所有 semantic 行 `step=0`，peer 覆盖除本 rank 外的所有 mesh peer，
  normal/atomic/direct 的 algorithm 标签不能混用。

### 6.4 NHR

- 配置 `HCCL_ALGO=level0:ring;level1:NHR`，选择日志必须出现 `AllReduceComm` 以及
  `COMM_COMBINE`（910B）或 `COMM_COMBINE_ORDER`（910C）；如果仍选择 Ring/Mesh executor，说明
  当前单机拓扑不可达，不能把空 NHR 语义当作测试失败或成功。
- 小数据使用总字节数 `<=256 KiB`，建议 ID：`DT-910B-AR-NHR-ONESHOT-8P-001`、
  `DT-910C-AR-NHR-ONESHOT-8P-001`；日志必须命中 `TEMPLATE_ALL_REDUCE_NHR_ONESHOT`。
- 普通 NHR 使用总字节数 `>256 KiB`，建议 ID：`DT-910B-AR-NHR-8P-001`、
  `DT-910C-AR-NHR-8P-001`；日志必须命中 `TEMPLATE_ALL_REDUCE_NHR`。
- 对 8 rank，普通和 Oneshot 每个 phase 的 `step` 集合预期为 `0,1,2`；每行 peer 必须来自
  该 hop 的实际 link。两种 algorithm 标签不得混用。
- 分别抽查 inline-reduce/SDMA 与非 inline/RDMA 分支；如果单机平台只可达其中一种，保存
  transport 选择证据，另一种保留为后续多机用例。

## 已确认的问题

旧 dual-v2 把整份采集中的资源/Host 提案竞争为一个最高分机制或局部簇。
其他迭代的波动会挤出真实变慢的位置；但取消 Top1 本身不能控制误报。

本轮真实回放还验证了两个不能直接采用的限制：

- 对整次通信的所有执行任务求和，会用正常阶段稀释局部 SDMA 慢化。
- 强制要求跨 Rank 慢 Wait 路径，会排除真实的局部执行慢化。
  在 1002 原图上，这一草稿输出 31 个有路径候选，但严格评测仍为 0/31。
  缺少传播见证不能被改写成“该任务没有变慢”，也不能补造依赖。

另外，局部任务的 1.5 倍规则不能不加区分地施加到整次通信区间。
1002 的 304 个初选语义单元所对应的调用区间，最大只达到自身历史均值的约 1.166 倍；
要求整次通信也达到 1.5 倍会把它们全部删除。这个结果不证明没有性能影响。

## 研究策略

新增显式 `--source-policy parallel`，默认仍为 `legacy`，旧 `dual`/`dual-v2` 不变。
这不是推荐替换版本，也没有部署到正在运行的实验队列。

1. 仍使用原任务比较事实、精确任务身份和前五个正式迭代。
2. 在一个公开通信调用内，按 algorithm/phase/event/task kind 分组，比较完整可比任务群，
   而不是仅对已经判慢的任务求平均。要求 1.5 倍/3MAD，且至少两个任务自身判慢。
3. 同 Rank、同迭代、同通信组的同类单元须在至少两个公开调用中共同出现。
   该可比任务群的总执行工作量还须超过其对应前五轮总量的 20% 和 3MAD。
   工作量和可能包含并行执行，不能当作通信耗时或训练损失。
4. 候选所在调用的本地设备任务包络须有正增长，且超过前五轮包络的 3MAD。
   此处不再要求调用整体达到 1.5 倍；它是调用增长的辅助证据，不是硬件因果证明。
5. 所有通过条件的候选平行保留，没有全局获胜者。传播只沿原始支持的依赖边展开；
   任务自身慢化与已经证明的等待路径分别报告。
6. Host 继续使用原严格公开准备/API/Notify 证据校验，不把 RDMA 提交当成网络完成。

此策略偏向持续、多任务、多调用的异常；孤立或很短的真实异常可能漏检。
没有独立正常多机数据的误报率校准，不保证 3MAD 能控制整份采集的多重比较误报。

## 全部结果

样本是本轮开始时已完整归档的 12 例低日志采集快照，不是实时队列进度。
其中资源相关 9 例用于下表，另 3 例 Host 的执行事实也回放留存，但未重做 Host 区间
端到端评测，不能把执行任务未命中记成 Host 漏诊。旧 INFO 首例 901 不混入。

| 样本类型 | 旧候选命中/全部候选 | 新研究版命中/全部候选 | 旧任一命中 | 新任一命中 |
|---|---:|---:|---:|---:|
| SDMA 竞争 | 3/8 | 141/1033 | 1/3 | 3/3 |
| 通信竞争 | 0/16 | 68/1146 | 0/4 | 3/4 |
| RoCE 限速样本内的执行任务 | 0/6 | 4/1038 | 0/2 | 1/2 |

通信竞争按预声明的两个参与 Rank 分别使用原始实际活动窗口评测。
68 个命中中，48 个位于主注入 Rank，其余 20 个在另一参与 Rank；不再发布候选优先级指标。
RoCE 行只是内部执行任务与限速窗口重叠，**不表示已定位网络端口或物理根因**。

新策略提高了“有一个候选碰到注入位置”的比例，但仍有大量非注入位置候选。
SDMA 的候选重叠比例约 13.65%，通信竞争约 5.93%，不能称准确率优化成功。
不能仅报告 3/3 或 3/4，也不能将不输出候选算成功。

没有删除任何实验组。事后噪声审计记录其他位置的相对增长是否更大，
但不同任务群的倍数不是绝对影响大小；该标志不足以自动宣布整组无效。
如后续使用“较干净子集”，须预先固定与注入真值无关的质量规则，并同时保留全量结果。
本快照的原计划仍是 19 例：12 完整、1012 技术失败、6 未运行；这不是重新完成 19 例。

## 输出与复现

所有新发布的 HTML 和文字报告不再显示“主候选”。候选编号只用于浏览，不表示优先级。
公开 JSON 增加 `candidate_relationship=parallel`；为兼容旧读取器，历史 `primary_*_id`
字段保留为 null，`source_selection` 不再公开单个 `primary_proposal`。
旧封存报告不原地重写，新展示副本另存，避免破坏其原始哈希。

研究入口示例，仅对已有完整 capture 进行离线分析：

```bash
hccl-diag analyze --capture /data/capture --mode rolling \
  --source-policy parallel --keep-debug --selected-iteration-view \
  --output /data/parallel-research-report
```

原始数据逐文件验证过的归档仍保留。此次先封存 public-fact selection，再独立读取真值评测。
完整任务比较 CSV 的 SHA 再次核对；另从每例全部比较行提取了 5200 个正式调用包络。
这是既有 artifact 的决策重放，不是重新解析全部原始 DB 或重新验收设备采集。

本地完整工作目录：`test/out/multinode-parallel-20261108/`。
各草稿分别位于 `replays`、`phase-replays`、`corroborated-replays`、`resource-replays`；
最终辅助调用包络的研究版为 `impact-replays`，评测为 `impact-evaluation.json`。
`call-span-replays/1002` 保留了错误地对整次调用施加 1.5 倍门槛后无候选的失败草稿。

三份真实原生报告重建在 `artifacts/multinode-parallel-20261108/impact-1005/report/`。
它们是所选通信调用的原图切片，**不是完整迭代图**；331 个候选、70 条完整原始依赖路径，
独立候选重叠 41/331。原始全图和输入不删除。
`1002/report` 是已否决的跨 Rank 路径硬门槛草稿，`1005/report` 是未加调用包络约束的草稿，
均不能冒充最终研究版。

## 后续顺序

先解决 SDMA/通信竞争的误报控制，再研究 RoCE。当前不要继续围绕已知注入位置改阈值。
需要区分“小但真实的局部增长”“可观测的通信完成影响”和“可证明的源头传播”，
并用独立正常多机输入检查误报；现有局部效应门禁不等价于整个通信或训练明显变慢。
RoCE 还缺少能排除端点迟到、接收端背压的路径级证据，不能用任务时长或候选命中代替。

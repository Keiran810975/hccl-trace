## 3. 已固化的身份合同

### 3.0 Schema 与本地序号清理

- semantic 生产 schema 为 v4；消费端兼容 v2/v3/v4，拒绝 v1 和无版本输入；
- `semantic_seq/profiler_seq` 已从生产结构、plog 和公共 CSV 删除；
- direct 去重由 physical merge key 保证，FFts 由 graph/context identity 保证；
- 两套 per-device 65,536 `atomic<u64>` 序号表和进程 fallback 序号已删除；
- `graph_instance_id` 继续保留，它是 FFts graph identity，不属于已废弃 task sequence。

### 3.1 Physical execution

```text
(node_id, device_id, physical_stream_id,
 task_id, subtask_id, connection_id)
```

生成稳定 `graph_id=x_*`。时间、CSV 行号和本地 operation ID 不进入身份。

### 3.2 Collective operation

正式采用 msprof DB：

```text
(group_name, op_name)
```

派生不暴露原始名称的 `profiler_op_scope`，状态为
`unique/missing/ambiguous`。已撤销生产端 `op_instance_id/retry_generation` 机制。

### 3.3 Notify

```text
resource = (node_id, notify_id)

direct channel =
  (node_id, operation_scope,
   producer_rank, consumer_rank, notify_id)

direct relation =
  (channel, db_notify_ordinal)

FFts relation =
  (operation scope, rank direction, signal,
   phase/step/slice, notify, graph instance)
```

`connection_id` 只属于 physical execution identity，不属于 Notify relation。

## 4. Execution graph

### 4.1 节点

保留所有有 profiler 时间的 `matched/profiler_only` physical execution，包括：

- SDMA/RDMA/Reduce；
- Notify record/wait；
- event record/wait；
- profiling control；
- 当前没有 HCOMM semantic 的真实 DB task。

重复 execution identity 是硬错误。

### 4.2 默认边

| kind | 规则 | confidence |
|---|---|---|
| `direct_stream_order_observed` | 同 node/device/physical stream，相邻 start bucket 且不重叠 | observed |
| `ffts_logical_stream_order` | 同 operation/graph parent/semantic logical stream，按 context 声明序 | semantic |
| `ffts_notify_sync_observed` | 完整 FFts relation 下唯一 producer/consumer | observed |
| `direct_notify_sync_exact` | DB channel 两侧单 stream、等数量、唯一 local ordinal | exact |
| `peer_payload_semantic` | peer/phase-group/step/slice 相同且 occurrence 数量一致 | semantic |

默认图已经删除：

- connection/time Notify 推断；
- FFts parent physical-stream 伪全序；
- `peer_signal_semantic` 重复控制边；
- right-neighbor、previous-step、phase-bridge 等算法假设边。

## 6. Execution artifact

固定输出：

```text
dep_graph_nodes.csv
dep_graph_edges.csv
dep_graph_notify_ambiguities.csv
dep_graph_summary.csv
```

节点和边均使用稳定摘要并按 ID 排序。Edge identity：

```text
(graph_schema_version, kind, src, dst, relation_id)
```

summary 统计：

- node/edge 与各 edge kind；
- duplicate node/edge；
- missing endpoint、self-loop；
- root/leaf/isolated；
- cycle residual；
- Notify relation 状态。

重复 ID、missing endpoint 或 self-loop 阻止 artifact 导出。

## 7. Resource graph

### 7.1 节点

当前资源白名单：

```text
sdma, rdma, reduce_inline, reduce_tbe
```

真实资源节点复用 execution `graph_id`。缺少唯一资源端点时可生成稳定 boundary。

### 7.2 收缩

仅沿：

```text
direct_stream_order_observed
ffts_logical_stream_order
```

搜索首个 resource frontier。

- 唯一 upstream + 唯一 downstream：生成收缩边；
- 缺一侧：生成 boundary；
- 多 frontier：写 resource ambiguity，不做候选笛卡尔积。

Resource edge 保存原始：

- execution edge ID；
- control node ID；
- record/wait node ID；
- relation/evidence/confidence；
- semantic annotation。

### 7.3 Resource edge kind

```text
resource_stream_order_observed
resource_ffts_order_observed
resource_notify_sync_exact
resource_notify_sync_observed
resource_payload_semantic
```

## 8. 同步等待指标

Notify resource edge 输出：

```text
wait_span_ns
remote_block_ns
post_signal_ns
handoff_gap_ns
weight_ns
timing_status
```

合同：

```text
wait_span = max(0, wait.stop - wait.start)
weight = wait_span

remote_block =
  clamp(record.stop - wait.start, 0, wait_span)

post_signal = wait_span - remote_block

handoff_gap =
  max(0, downstream_resource.start - wait.stop)
```

同节点为 `same_node_observed`。跨节点未校准时为
`cross_node_uncalibrated`，不输出 remote/post 跨时钟分解。

`remote_block/post_signal` 是围绕 record 完成时刻的观测分解，不等价于 Notify 硬件可见
时刻。

## 9. 双视图与 artifact 单一事实源

HTML/SVG 已支持：

- execution view：完整 physical/control task；
- resource view：资源任务、收缩边、等待指标和 evidence。

可视化只读取导出的 node/edge CSV，不在布局层重新构边。真实资源任务在两种视图中共享
稳定 `graph_id`。

更新后的功能测试 wrapper 会：

1. merge；
2. 导出 execution/resource artifact；
3. 运行 dependency gate；
4. 从 artifact 渲染两种 HTML/SVG；
5. 运行 semantic merge gate。

## 10. Dependency gate

新增 `validate_dependency_graph.py`，门禁：

- execution/resource duplicate ID；
- missing endpoint；
- self-loop；
- cycle residual；
- Notify ambiguous/incomplete/conflict；
- resource contraction ambiguity；
- 可配置 boundary 上限；
- FFts physical-stream 伪顺序；
- 默认 time-inferred；
- 旧 `notify_sync_inferred/peer_signal_semantic`。

输出 stream、sync、payload、boundary 和伪边统计，支持 `--golden-summary` 精确比较。

## 14. 已知边界

1. `peer_payload_semantic` 仍按同语义坐标的 occurrence 顺序配对，不是共享 token exact relation。
   当前匹配键未纳入 operation scope，数量不等时也没有 payload ambiguity artifact。
2. `ffts_logical_stream_order` 表示 context 声明序，不代表不同 logical stream 的硬件依赖。
3. resource 收缩当前把 FFts/mixed order 派生边写为 `observed`，错误增强了源
   `semantic` 证据；后续必须按路径最弱 evidence 传播并升级 graph schema。
4. 多节点尚无统一 `profile_run_id` manifest 和时钟校准 artifact。
5. resource whitelist 尚未覆盖所有可能的 compute/transport task kind。
6. 当前尚未在 resource graph 上实现正式 critical-path 与等待归因报告。

以上限制必须通过增加事实证据或独立校准解决，不能恢复时间最近 heuristic。

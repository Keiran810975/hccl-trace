## 改动与边界

及其`parallel`别名保持不变；没有改服务器活动快照、采集包、训练或注入。
修改前备份`test/out/multinode-cohort-20261108/backup/before-cohort-policy.tar.gz`，SHA256
`92ce7a2844823eb0a4c0dea1e51598f70cd88ecddbacf2897c670dc91e75104d`。

## 固定规则

1. 复用原始`build_clusters`，保留前五轮1.5倍/3MAD、任务身份、真实依赖、调用/局部性边界。
   每例全部簇ID与原封存结果一致，不改簇成员、不跨Rank合簇、不补因果边。
2. 去掉原`_burst_context`邻近慢任务计数乘数。原任务相对增长截顶、过去报警折扣、
   stream/任务类型内均值、证据单元数和簇内时间密度仍用于资源簇基础分。
3. 按公开`Node/device/Rank/group_id/正式iteration`收集全部已观测HCCL内部WORK任务，
   包括未变慢任务，不只取预选任务。每条任务除以自身精确前五轮均值后，对全量因子取P95。
   该上下文是当前完整轮的离线观测，可能含源头之后的任务，不证明这些任务先发生或共享物理原因。
4. 只有至少20条任务且全部具有经过身份核验的前五轮参考时才使用P95；不足20条时
   nearest-rank P95会退化成最大值，故不给额外支持。身份缺失或总体历史不完整也取中性支持。
   不从Rank猜设备/通信组，不忽略缺失正常任务来抬高P95，不使用未来轮的观测。
5. 资源簇新分数固定为`原资源基础分（不含邻近乘数） * (1 + ln(max(1, 全量任务群P95)))`。
   P95不是硬准入门槛，不直接发布整轮208个任务；它仅支持原簇的排序。
6. Host仍使用原严格公开准备/API/唯一Notify/慢Wait支持校验及原评分，未改其阈值。
   最后仍只选一个最高分簇或Host区间；簇内候选平行，无任务优先级，同分按稳定ID。
7. 原有有向路径及时间门禁重建传播证据；协议路径仍作观测，不宣称RDMA硬件完成或物理故障定位。

这些因子是排序启发式，不是训练损失、独立样本显著性或已校准误报概率。

```bash
hccl-diag analyze --capture /data/capture --mode rolling \
  --source-policy cluster-top1-cohort --selected-iteration-view --keep-debug \
  --output /data/cohort-report
```

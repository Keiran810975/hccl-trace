# 多机源头诊断离线优化

## 范围

仅使用2026-11-03 Node0+Node3、8 Rank GPT-2 Small的520队列留存事实，未重跑训练或部署。
521正常；522 Copy；523通信竞争；524计算竞争；525调用前迟到；526原生RoCE限速。
每例10轮预热+50轮正式。原始采集、图、旧报告和各轮离线方案均保留，不覆盖失败结果。
这六组用于开发，不是独立准确率验证集。

## 规则

入口为`multinode_source_refinement.py`，显式`--source-policy dual-v2`；通用CLI默认legacy不变。

1. **保持事实与阈值。** 相同公开group/call/occurrence/phase/step定位，与前5个正式轮次比较；
   执行预选仍1.5倍/3MAD，没有绝对时长增量门槛。没有注入类型、目标Rank或注入窗口参数。
2. **分开源头和症状。** 接收端协议等待、发送提交至数据通知的校准区间单列为路径观测，
   不与执行源头竞争，不称为RDMA硬件传输耗时或NIC故障证据。
3. **找共同慢化的局部簇。** 复用真实依赖上下文的资源簇，按stream/task-kind分组；每组取
   稳健相对增量的有界对数均值，按该任务历史报警比例降权，再结合簇的原时间密度。
   相对增量在评分时最多计150%，避免接近零的历史均值支配全部排序；不改变原任务耗时。
4. **用历史节奏识别突发。** 同Node/Rank/device/group的前5轮公开调用正间隔中位数作为
   局部半径，比较附近其他慢任务数与历史期望数量。相邻共同慢化给评分加权，频繁随机慢化
   降低区分力；没有完整历史或通信域时不加权。这个窗口不使用注入时长，也不扩展候选区间。
5. **Host迟到单独验证。** 公开准备区间须绑定实际API，并有唯一Notify到慢peer Wait的
   原依赖支持；按自身稳健慢化、与Wait增量重叠比例及支持数量评分。Host是独立区间，
   task/stream为null；只用真实设备锚点展示，不伪造Host→设备边。
6. **只发布首选机制/簇。** 保留该簇全部成员；其他提案留审计。无传播亦可成为局部执行候选。
   这是相对定位，不是已经校准的“存在物理故障”报警器。
7. **从原图重新核验传播。** 对已选源头向下核验真实有向路径，Wait用20%观察门槛。
   进入Notify Wait必须经唯一实际生产端，而不是同流前驱；不能越过无关生产端补链。
   核验每条边的顺序、端点、轮次与时间门禁，缺证据明确停止。跨机校时保留估计误差，
   不累计全局workload关键路径，不将拓扑可达等同全部等待增量归因。

## 离线复核

公开事实缓存采用文件白名单和原始manifest逐项SHA256，分析器不读取注入控制或评测文件。
先封存相同消费者的六组结果及哈希，再由独立评测器读取真值，按同Node/Rank正重叠判定。
原始图不重构；报告切片从原图原ID/边提取，JSON保留输入哈希与
`raw_db_or_dependency_reconstruction_performed=false`，不冒称重新DB验收。

| 异常 | 原窗口命中/候选 | 独立限速窗口核正后 | 实际路径 |
|---|---:|---:|---|
| Copy竞争 | 3/3 | 3/3 | 未证实慢Wait传播，不补边 |
| 通信竞争 | 8/8 | 8/8 | 5条完整原图路径 |
| 计算竞争 | 0/4 | 0/4 | 未命中，选到第37轮而非注入轮 |
| 调用前迟到 | 1/1 | 1/1 | 1条带校时限制路径；候选单位为Host区间 |
| 原生RoCE限速 | 0/6 | 6/6 | 未证实慢Wait传播，不补边 |

原窗口合计12/22=54.55%，3/5例；另列核正口径18/22=81.82%，4/5例。
核正口径分单位为执行task17/21、Host准备区间1/1，不能把Host说成设备task。
正常组仍输出4个执行候选，尚未解决误报。计算组不能靠改注入坐标或筛掉失败分母来算成功。
独立评测后复核计算组排序：Rank4第25轮的最强执行簇只有1个预选任务、分数0.6173，
首选第37轮为4个任务、4.1431分。说明这次输入中非注入位置的共同慢化证据更强，
不是继续追溯一条未记录的边就能解决；尚需独立样例及正常波动建模验证。

### 限速窗口审计

旧控制器先读回20Gbps，再查另一芯片及流量counter，最后记录`started_raw_ns`。
该字段实际是counter采样开始，不能完整代表已经生效的限速开始。原控制日志逐文件核验后，
首次成功读回20Gbps为RAW `4626429345764340`，原开始为`4626429965006330`，
相差619241990ns。独立审计只用控制日志，不读候选来选窗口；结束时间不变。
原窗口和0/6原结果完整保留，核正结果单列。未来控制器已增加
`first_confirmed_limit_raw_ns`，评测器优先使用；旧记录fallback不变，本轮未部署重测。

## 使用

```bash
hccl-diag analyze --capture /path/to/capture --mode rolling \
  --source-policy dual-v2 --output /path/to/new-report
```

输入仍须包含原DB/语义、公开调用绑定及适用的独立校时；该命令不替代采集。
最终仅`execution.html`、`root_causes.json`、`propagation.html`。默认不改源采集，
没有注入真值也能运行。可按`cli.py`的`--keep-debug`选项留存审计中间数据。

本次报告/双口径逐候选评测索引在根目录
`artifacts/multinode-refinement-20261103-001/README.md`；早期方案及失败审计在
`test/out/multinode-refinement-20261103-001/`。后续需要独立种子复核和正常报警校准，
不能将这次已知样例的18/22宣称为一般准确率。

# 候选精度验收与固定事实消融

## 预先固定的规则

用户验收目标为命中根因任务数/输出候选任务数严格大于75%。沿用同Node、同Rank、
观测任务区间与实际注入确认区间正重叠；不同Rank的通信对端不能代替执行Rank。
候选为空的异常例是未定位，不将0/0计为100%；同时报告异常例命中覆盖、过滤掉的真阳性
和正常对照报警数。任务级计数不通过合并为一个候选段改变分母。

本次使用已看过结果的历史采集，只能作探索性开发，不声明独立验证达到75%。
分析阶段不读注入窗口或评测文件；各方案全部执行结束并保存选择结果后，评测阶段才读取真值。
原始事实、原报告、全部原候选和未入选理由保留，不以筛选结果覆盖旧证据。

首轮四种固定方案，不进行按真值自动搜索参数：

1. `all`：原有可信通信内部、真实依赖支持的源头候选。
2. `critical_path`：仅保留本节点/本调用局部模型slack=0者；缺模型时明确证据不足。
   不混淆“slack=0”和“单任务加速有正收益”，也不宣称全局训练关键路径。
3. `history_envelope`：原有前5轮均值/1.5倍/3MAD判慢不变，额外要求当前源头耗时
   大于前5轮同定位任务的最大值。旧范围内的均值报警降为观测，不冒称统计显著。
4. `envelope_dominant_region`：先用上项，再按原有同Node/Rank/通信组相邻轮次候选段，
   去重累计min(源头增量,受影响Wait最大增量)预算。唯一最大段预算至少为第二段3倍且
   为正才入选，段内保留所有任务；没有明显主导段则不定位，而非无条件取top1。

首轮仅查看各方案数量、尚未运行本轮真值评测时，加入第五项`wait_critical_path`消融：
只把原传播链末端的同Node/同调用Wait作为模型终点，缩短源头自身执行增量后，若该Wait
模型完成时间提前才保留。不同于对整调用终点的slack过滤，这避免无关长尾遮蔽局部传播；
跨机/跨调用路径或缺边明确不可评，不生成全局关键路径。不以它作为自动提高精度的保证。

这三种过滤均为实验选项，不自动更改正式CLI的默认候选或阈值。尤其关键路径可能滤掉
真实局部通信异常；若观察到这一点，就不把它作为必需门槛。孤立慢任务在当前policy7的
公共内部候选中本来已被排除；可选local-completion支持另有明确合同。

## 数据与边界

- 固定单机Copy512采集：保留完整graph及公开iteration-map，可用当前消费者重新回放。
- 固定多机240/241短Copy：全部原始输入及两机备份保留；240阴性、241执行Rank不等于注入Rank。
- 固定201正常GPT第10/45轮及各自前5轮：负控，不是50轮全量回放。
- 五组旧多机GPT仅保留最终报告，原始DB/完整图已清；只能审计原候选筛选，不能冒称当前全图回溯。
- 单机30组GPT原始图已清；可保留原指标，但缺少所需历史/关键路径证据时必须注明不可评测。

所有离线结果必须保留零候选、失败、历史不足、未运行，不挑选最好的样例报总体精度。
默认方案是否更改的门槛：有真实阳性不被筛掉、正常对照报警减少、固定样例精度达标；
之后还需不同种子/未用于开发的数据确认，才能称单机/多机普遍达标。

## 实测结果与处置

最终消费者固定后完成5份原图回放。`final/`下每份先保存输入/消费者哈希、全部源头观测、
五种方案的所有决定和决定文件哈希，再由独立入口读取窗口评测；评测前后核对决定哈希。
这是同一工作者的探索性回放及自审，不声称由隔离执行环境或独立研究者审计。

| 方案 | 单机Copy命中/入选 | 多机241命中/入选 | 正常GPT两窗口入选总数 |
|---|---|---|---|
| 原规则 | 11/57（19.30%） | 0/1 | 19 |
| 调用级关键路径 | 3/3（100%） | 0/0，未定位 | 9 |
| Wait终点关键路径 | 5/42（11.90%） | 0/1 | 13 |
| 历史包络 | 9/52（17.31%） | 0/1 | 19 |
| 历史包络+主导段 | 0/0，未定位 | 0/1 | 2 |

多机240五种方案均为0候选，保留其无明显执行慢化的阴性结果，不算定位成功。
单机固定样例不是本次重跑GPT的40组；旧单机30组大型原始图已清，不能把以上百分比
替换其历史统计。正常窗口只选了两轮，不能据此计算全50轮误报率或声明环境无外部干扰。

调用级关键路径在单机这个固定样例超过75%，但筛掉8个原本命中的任务（仅保留3/11），
也筛掉多机唯一真实局部慢任务；正常窗口仍有9候选。因此不推广为默认条件。
Wait终点模型能保住多机源头，但单机精度下降；历史包络对真实局部抖动几乎无效；
主导段会漏掉单机阳性，并仍保留多机未命中候选。没有任何一项可称单机/多机共同达标。

多机241的当前唯一源头执行Rank5，注入执行于Rank4；Rank4自身工作最大约1.02684倍，
未过原1.5倍判慢条件。该例不是通过过滤现有候选就能得到同Rank真阳性：筛选只能保留
或删除Rank5，不能把对端Rank4改成慢任务执行方。独立时间校准矛盾和逐笔RDMA完成
证据不足依然保留，未为提高比例放宽时间门禁或补边。

## 可复现入口

正式默认仍是`--candidate-policy all`。其他模式均为显式实验选项，不宣称已达标：

```bash
hccl-diag analyze --capture /path/to/capture --mode rolling \
  --candidate-policy critical_path --output /path/to/fresh-report --keep-debug
```

最终仍只有execution.html、root_causes.json、propagation.html。公共JSON保留
`candidate_admission`、全部筛选决定和`deferred_communication_source_observations`中的
完整原候选观测及依赖路径。未入选不等于已证为正常，不能把筛空解释为没有异常。
原始发现层和rolling中间报告不删除原候选；原图不改，源头执行位置不重新指派。

离线公平消融（先跑完再评测）：

```bash
python3 -m test.benchmark_candidate_screening \
  --artifact /path/to/validated/analysis --iteration-map /path/to/public-iteration-map.json \
  --output /path/to/fresh-ablation
python3 -m test.evaluate_candidate_screening \
  --analysis /path/to/fresh-ablation --windows /path/to/evaluation-only-windows.json \
  --output /path/to/fresh-ablation/evaluation.json
```

独立窗口采用列表，每项需node_id、target_ranks、start_ns、stop_ns。默认与候选同为profiler
整数纳秒；若窗口是MONOTONIC_RAW，则评测加`--alignment`使用独立设备元数据偏移。
不把Host包络冒充单次设备Copy区间。分析器命令没有注入窗口参数。

全部数值、原观测、被筛任务和校验在`test/out/candidate-precision-20261101/final/`。
可选策略实际发布验证在`public/single-critical/`，保留54项deferred观测。
当前为本地nf未提交改动，没有同步服务器、重新训练/采集或推送GitHub。
